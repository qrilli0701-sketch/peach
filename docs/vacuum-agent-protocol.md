# 청소기 구매 컨설팅 멀티 에이전트 프로토콜

## 구성

```
                    ┌──────────────────────┐
                    │   vacuum-chief (대장) │
                    │  요건 확정 · 최종 결론  │
                    └──────────┬───────────┘
             1차 병렬 파견 (동시 실행)
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ spec-scout   │ │field-validator│ │ alt-explorer │
│ 스펙·가격 수집 │ │ 실사용·A/S·유지비│ │ 경쟁 대안·편향깨기│
└──────┬───────┘ └──────┬───────┘ └──────┬───────┘
       └────────────────┼────────────────┘
                        ▼  2차: 교차 반박
              ┌──────────────────┐
              │ red-team-critic  │
              │  상충·근거·편향 판정 │
              └────────┬─────────┘
                       ▼  3차: 지적받은 에이전트 재확인(컨텍스트 유지)
                  최종 산출물 1개
```

## 핵심 규칙

### R1. 요건이 리서치보다 먼저다
6축(평수·구조 / 바닥재 / 반려동물 / 예산 / 최우선가치 / 설치제약)이 확정되지 않으면 추천은 무의미하다.
사용자가 안 알려주면 **가정값을 선언하고 진행**한다. 되묻기만 하고 멈추는 것은 실패로 간주.

### R2. 병렬은 진짜 병렬
1차 파견 3기는 한 응답에서 동시에 띄운다. 서로의 결과를 기다리게 만들면 앵커링이 전파된다.
1차에서는 서브 에이전트끼리 정보를 공유하지 않는다 — **독립 표본**이어야 교차 검증이 의미를 가진다.

### R3. 숫자에는 출처, 없으면 "미확인"
가격·흡입력·소음·배터리는 URL + 확인 날짜 병기. 추측값 삽입은 최상위 위반.
해외 모델 스펙을 국내 모델에 전용하지 않는다(모델명·구성이 다른 경우가 흔함).

### R4. 반대 역할을 고정 배치한다
`field-validator`는 비관, `alt-explorer`는 반대편 변호인, `red-team-critic`은 파괴자.
전원이 동의하는 결론은 검증된 것이 아니라 **집단사고**를 의심해야 한다.

### R5. 교차 피드백은 생략 불가
레드팀 라운드 없이 최종 산출물을 내지 않는다. 상충 지점은 은폐하지 않고 **판정 근거와 함께 노출**한다.
아무도 확인 못 한 수치는 최종물에서 삭제하거나 "미확인"으로 남긴다.

### R6. 결론은 하나
1순위 1개 + 조건부 대안 2개. 그 이상은 고민을 사용자에게 되돌려주는 것이다.
1순위에는 **철회 조건**("이 조건이 사실이면 추천이 바뀐다")을 반드시 붙인다.

### R7. 링크를 준 브랜드가 정답일 필요는 없다
사용자가 특정 스토어 링크를 줬다는 건 앵커링 신호다. 사실이 다른 결론을 가리키면 그렇게 말한다.
반대로 억지 대안도 만들지 않는다 — 지목 브랜드가 합리적이면 그렇게 보고한다.

### R8. 마케팅 언어 금지
"역대급", "최강", "혁신" 같은 표현은 스펙란과 결론에서 배제. 협찬 리뷰는 신뢰도 태깅.

## 실행 방법

```
# 대장에게 위임 (대장이 나머지를 병렬 파견)
Agent(subagent_type="vacuum-chief", prompt="원룸 8평 장판, 고양이 1마리, 예산 80만원. 청소기 추천해줘")
```

부분 조사만 필요할 때는 개별 호출도 가능하다.

```
Agent(subagent_type="spec-scout",    prompt="드리미 로봇청소기 현행 라인업 가격/스펙")
Agent(subagent_type="field-validator", prompt="드리미 A/S·유지비 리스크")
Agent(subagent_type="alt-explorer",  prompt="80만원대 드리미 대안")
```

## 실패 모드와 방어

| 실패 모드 | 방어 장치 |
|---|---|
| 스마트스토어 JS 렌더링으로 본문 수집 실패 | spec-scout 조사 순서 2단계(공식몰·가격비교·기사)로 즉시 우회 |
| 브랜드 홍보문 재생산 | R8 + field-validator의 협찬 태깅 |
| 서브 보고서 단순 이어붙이기 | R5 레드팀 라운드 + 대장의 상충 판정 의무 |
| "취향에 따라 다름"으로 끝나기 | R6 단일 결론 + 철회 조건 |
| 유행 모델 앵커링 | R2 독립 표본 + R7 |
| 오래된 가격으로 결론 | R3 확인 날짜 의무 + 레드팀 가격 신선도 검사 |
