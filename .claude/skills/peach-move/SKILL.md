# 주문접수 → 27년주문 이동 (감사관 2인 합의)

## 제1원칙

틀린 값 하나가 빈 칸보다 나쁘다. **사용자가 "넣어"라고 하기 전에는 27년주문에 쓰지 않는다.** 이름·주소는 고치지 않는다. 자동 보정은 전화번호 하이픈(11자리일 때)뿐이다.

## 절차

1. **준비(시트 읽기만)**
   ```bash
   cd peach-bot && python3 move_orders.py prepare --out <스크래치패드>/move.json
   ```
   주문접수에서 상태가 `확인`인 줄만 27년주문 형식으로 변환한다. 후보가 0건이면 거기서 끝, 사용자에게 알린다.

2. **1라운드: 감사관 둘을 병렬로 호출**
   - `peach-move-auditor-a`(원본 충실도), `peach-move-auditor-b`(중복·형식·위험)
   - 프롬프트에는 **move.json 의 절대경로만** 넘긴다. 내 의견·요약은 붙이지 않는다(끌려가지 않게).

3. **합의 판정(줄마다)**
   - 통과: A와 B가 모두 **90점 이상**이고 둘 다 `검증필요: 아니오`.
   - 그 외: 토론.

4. **토론 라운드(최대 4회)**
   - 통과 못 한 줄이 있으면, A에게 B의 검토문 전문, B에게 A의 검토문 전문을 넘겨 다시 호출한다(둘 다 한 번에 병렬로, 서로의 직전 라운드 검토문을 전달). 해당 줄 위주로 반박·인정·점수 재산정을 하게 한다.
   - 줄마다 합의가 나면 그 줄은 통과, 아니면 다음 라운드. 4라운드가 끝나도 합의가 없으면 **보류**.
   - **조기 보류:** 한 라운드 토론 뒤에도 같은 줄이 같은 이유(사용자만 답할 수 있는 것: 중복 여부, 빈 칸, 이상한 전화번호)로 90 미만이면 더 돌지 않고 바로 보류한다. 점수를 올릴 근거가 사용자의 답뿐이기 때문이다.
   - A 점수(원본 충실도)와 B 점수(중복·완결성)는 기준이 다르다. 평균 내지 않고 **둘 다 90 이상**일 때만 통과다.
   - 다음 라운드에 상대 검토문을 넘길 때는 파일로 저장해 경로를 주되 **내용을 줄이거나 고치지 않는다**.
   - 에이전트 목록에 peach-move-auditor-a/b 가 안 보이는 세션(파일을 만든 직후 등)에서는 `general-purpose`(model opus)에게 해당 `.claude/agents/*.md` 를 Read 해서 그 지침대로 하라고 시킨다. 읽기 전용이라고 명시한다.
   - 감사관의 점수나 문장을 내가 바꾸거나 다듬지 않는다. 한쪽을 이기게 하려고 유도하지 않는다.

5. **사용자에게 보고(시트 쓰기 전)**
   - 표 하나: 원본행 | 받는사람 | 전화 | 수량 | 주소 | 보내는사람 | A점수 | B점수 | 상태(통과/보류) | 라운드 수
   - 보류 줄은 이유와 함께 "사용자에게 질문"으로 따로. 빈 칸·중복 의심은 반드시 짚는다.
   - 마지막에 "통과 N건을 27년주문에 넣을까요?"

6. **사용자가 "넣어"** 라고 한 뒤에만:
   - move.json 의 통과한 줄에 `"통과": true` 를 넣어 저장하고
   ```bash
   cd peach-bot && python3 move_orders.py apply <move.json> --yes
   ```
   스크립트가 27년주문 백업 → 원본 줄이 그대로인지 확인 → 27년주문에 추가(날짜 바뀌면 구분 빈 행) → 주문접수 상태 `완료` → 되읽기 출력까지 한다. 출력을 그대로 보고한다. 실패하면 실패를 그대로 보고한다.
   - 빈 칸이 있는 줄은 27년주문에서 노란 음영 대상이다. 기록 후 `python3 peach.py highlight` 미리보기를 먼저 보여주고 사용자가 "해"라고 하면 `--commit` 한다.

## 금지

- 합의 전 기록, 점수를 올려 달라고 압박, 4라운드 넘는 토론, 보류 줄 강제 통과.
- 사용자 승인 없이 `--yes`.
