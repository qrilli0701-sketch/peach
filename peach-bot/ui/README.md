# 주문 화면 (UI)

주문을 **받아서 → 검토하고 → 택배업체에 보낼 파일로 내보내는** 화면.
기존 CLI(`peach.py`)를 대체하지 않고 그 위에 얹었다. 업무 로직은 전부 기존
모듈에 그대로 있고, 이 화면은 그걸 부르기만 한다.

## 실행

```
run_ui.bat              실제 구글시트 (.env 의 서비스계정 필요)
run_ui.bat --demo       가짜 데이터. 자격증명 없이 화면만 둘러볼 때
```

직접 실행하려면 `python ui/server.py [--demo] [--port 8765]`.
브라우저가 자동으로 열린다. 끄려면 창에서 Ctrl+C.

## 화면 3개

| 탭 | 하는 일 |
|---|---|
| **받기** | 주문 텍스트 붙여넣기 → 파싱 → 표에서 고치기 → 시트 기록 |
| **검토** | 시트 전체를 보며 빈칸·전화오류·중복을 눈으로 확인하고 칸을 바로 수정 |
| **출고** | 날짜 범위로 잘라 `.xlsx` / `.csv` 로 내보내기 |

### 받기

세 가지 형식을 읽는다. **줄마다** 판단하므로 섞여 있어도 어느 쪽도 버리지 않는다.

- JSON 배열 — 대화창에서 Claude 가 만든 결과를 그대로 붙여넣기
- 라벨 형식 — `받는분: 홍길동` / `연락처: 010-...`
- 자유 형식 — `홍길동 / 010-2345-6789 / 2박스 / 서울시 ...`

읽은 값은 **교정하지 않는다.** 자릿수가 틀린 번호는 고치지 않고 전화 칸에 원문
그대로 넣어 빨갛게 표시하고, 가려진 번호(`010...1234`)는 아예 채우지 않는다.

기록 전에 시트를 뒤져 **같은 사람+주소** 또는 **같은 사람+전화**인 기존 주문을
찾아 보여준다(중복 주문 방지).

> 이미지는 이 화면에서 못 읽는다. 판독은 여전히 대화창에서 Claude 가 한다.

### 검토

시트를 그대로 비추되 구글시트에서는 안 보이는 것을 얹는다.

- **노란 칸** — 비어 있음. 색은 시트의 음영과 같은 값(`rgb(255,242,153)`)
- **빨간 칸** — 전화번호 자릿수 오류 (`validate.check_phone` 과 같은 규칙)
- **파란 세로줄 + 중복 의심 #N** — 같은 사람+주소 또는 같은 전화번호끼리 묶음

칸을 눌러 고치면 구글시트에 바로 반영된다.

### 출고

시트 열을 그대로 내보낸다(택배사 고정 양식이 없어서). 하는 일:

- 날짜 범위로 자르기
- **빈 칸·전화번호 오류가 있으면 내보내기를 막는다.** 경고에서 확인하면 강행 가능
- 엑셀에서 전화번호 앞자리 0이 날아가지 않도록 **텍스트 서식**으로 저장
- 박스 수·금액 요약 (박스당 40,000 + 택배 5,000, 2박스까지 묶음)

## 안전장치

- **127.0.0.1 에만 바인딩**한다. 고객 개인정보라 같은 네트워크에도 열지 않는다.
- **삭제 기능이 없다.** 마우스로 지워지면 안 되는 데이터라 CLI 로만 남겼다.
- 기록 전 CSV 자동 백업. 낱개 수정은 10분에 한 번으로 조절(파일 폭증 방지).
- 받는사람이 빈 행이 하나라도 있으면 **전체 기록을 중단**한다 (CLI 와 같은 규칙).
- `입력시각` 열은 화면에서 수정할 수 없다.

## 파일

| 파일 | 역할 |
|---|---|
| `ui/server.py` | 표준 라이브러리 http.server. 기존 모듈을 부르는 얇은 껍데기 |
| `ui/index.html` | 화면 전체. 빌드 도구 없음 |
| `../parse.py` | 붙여넣기 텍스트 → 주문 JSON |
| `../export.py` | 날짜 필터·빈칸 검사·xlsx/csv 생성·금액 계산 |
| `../peach.py` | 시트 입출력 (CLI 와 공유 — `append_orders`) |
| `../validate.py` | 전화번호 검증 (CLI 와 공유 — `check_phone`) |

웹 프레임워크를 쓰지 않은 이유: 이 화면은 사장님 PC에서 더블클릭으로 떠야 한다.
새로 설치할 의존성은 `openpyxl` 하나뿐이다.
