# peach 작업 핸드오프

복숭아 주문 관리 작업을 다른 세션에서 이어가기 위한 인수인계 문서.
새 세션에서 이 파일과 아래 핵심 파일들을 읽으면 하던 지점부터 이어갈 수 있다.

## 다음에 할 일
HTML 인터페이스 1차 구현 완료(아래 "주문 화면" 참고). 남은 것:
- **`주문양식.txt` 를 단골에게 카톡으로 뿌려보고 반응 보기** — 접수 개선의 출발점
- `kakao.py` 를 사장님 실제 카톡 내보내기 파일로 검증 (기기 형식이 다를 수 있음)
- 사장님 PC에서 `run_ui.bat` 으로 **실제 시트에 붙여 확인** (원격 세션엔 `.env` 가 없어 데모로만 검증됨)
- 실제 주문서 텍스트로 `parse.py` 초벌 파싱 정확도 확인 — 형식이 다르면 규칙 보강
- 택배사 고정 양식이 생기면 `export.py` 에 열 매핑 추가

## 전체 워크플로우

```
① 고객이 카톡으로 주문        양식 없음. 캡처·사진·긴 글·여러 메시지에 흩어짐
        ↓
② 사장님이 Claude 에게 전달    ← 여기가 병목. 지금은 한 건씩 손으로 옮김
        ↓
③ 판독 (Claude / 판독팀)       이미지는 reader→checker→lead, 텍스트는 Claude 직접
        ↓
④ 확인 — 표로 보여주고 "넣어"  기록 전 반드시 사람 승인
        ↓
⑤ Google 스프레드시트 기록      validate.py 로 전화번호 검증 후
        ↓
⑥ 사장님 재검토                 ← UI '검토' 탭 (빈칸·전화오류·중복 표시)
        ↓
⑦ 엑셀로 내보내 택배업체 전달   ← UI '출고' 탭
```

②가 가장 오래 걸린다. ①의 양식이 없어서 ②를 사람이 대신 읽어 옮기기 때문이다.
따라서 개선은 **①을 덜 어지럽히거나, ②를 묶어서 한 번에** 하는 두 방향이다.

### 접수 — 무엇이 오든 파일로 떨구고 위험을 잰다 (2026-08-26 방향 전환)

입력을 통제하는 대신 **받는 쪽을 두껍게** 한다. 고객이 양식을 쓰든 말든
아무렇게나 보내면 그대로 올리고, 위험한 것만 골라 판독팀을 돌린다.

```bash
python intake.py --text -      # 붙여넣은 텍스트 (stdin)
python intake.py --images      # 붙여넣은 이미지
python intake.py --file <경로> # 이미 파일인 것
```

셋 다 `inbox/<날짜시각>/` 에 파일로 저장하고 **위험 신호**와 권장 경로를 돌려준다.

**이게 왜 필요한가**: 판독팀은 `Read` 만 가져서 경로 없는 입력을 못 받는다.
그래서 붙여넣은 텍스트는 늘 단독 판독이었다 — 가장 많이 들어오는 경로인데
교차검증이 0이었다. 파일로 떨구면 텍스트도 팀을 탄다.

**경로 선택은 기본이 판독팀이다.** 단독은 예외 — 텍스트이고, 라벨이 명확하고,
위험 신호가 없고, 건수가 적을 때만. 자세한 조건은 `SKILL.md` 0단계.

위험 신호(가려진 번호, `총 N박스` 합계, 카톡 원문 여부)는 **원문에서 직접** 잰다.
파싱 결과에 기대면 파싱이 실패하는 입력에서 신호를 놓치는데, 정작 그때가 제일 위험하다.

**카톡 원문을 규칙 파서로 주문 추출하는 건 불가능하다.** 한 주문이 여러 메시지에
걸치고, 잡담이 섞이고, "보내는사람도 동일함" 같은 문맥 참조가 있다. `kakao.py` 는
주문을 뽑지 않는다 — **보낸사람별로 묶어 구조화만** 하고, 해석은 Claude 가 한다.

## 시스템 개요
주문(카톡·이미지·붙여넣기 텍스트·엑셀·손글씨) → 판독 → 검증 → 스프레드시트 → 검토 → 출고.

구성원:
- **오케스트레이터(Claude 본체)** — 주문 받아 판독하고 흐름을 지휘, 기록 실행
- **판독팀 서브에이전트** (`.claude/agents/`) — `peach-reader`(추출) → `peach-checker`(원본 대조) → `peach-lead`(행별 기록/보류 판정). *파일 경로가 있는 이미지에만 사용 가능*
- **validate.py** — 기록 직전 검증 레이어
- **peach.py** — Google 시트 입출력 CLI
- **Google Sheet** — 최종 저장소

## 핵심 파일
- `peach.py` — 시트 CLI. 명령: `add`, `add-checked`, `count`, `recent`, `search`(중복확인), `delete-last`, `delete-name`, `clear`, `highlight`(빈칸 노란음영), `backup`, `restore`
- `validate.py` — 검증. 현재 **전화번호 자릿수만** 판정에 사용. `check_road_address`(juso), `check_sido` 함수는 남아있지만 호출 안 함(되살리려면 `validate_order`에서 다시 부르면 됨)
- `.claude/agents/peach-reader.md`, `peach-checker.md`, `peach-lead.md`
- `parse.py` — 붙여넣기 텍스트 → 주문 JSON (JSON/라벨/자유 형식을 **줄마다** 판단)
- `intake.py` — 접수. 텍스트·이미지·파일을 `inbox/` 에 떨구고 위험 신호를 잰다.
  **모든 입력이 여기를 지나야 판독팀을 탈 수 있다**
- `kakao.py` — 카톡 내보내기(.txt) → 보낸사람별 묶음. 안드로이드·아이폰·PC 형식 모두 읽음.
  사진 있던 자리, 가려진 번호, `총 N박스` 합계 표현을 표시해 준다. **주문 해석은 하지 않는다**
- `주문양식.txt` — 고객에게 카톡으로 뿌릴 주문 양식 (4줄)
- `export.py` — 날짜 필터, 출고 전 빈칸 검사, xlsx/csv 생성, 박스·금액 계산
- `ui/server.py`, `ui/index.html`, `run_ui.bat` — 주문 화면 (`ui/README.md` 참고)
- `.env` (git 제외) — `SPREADSHEET_ID`, `GOOGLE_CREDENTIALS_FILE`, `JUSO_CONFM_KEY`
- 시트 열: `입력시각 · 받는사람 · 받는분전화번호 · 수량 · 주소 · 보내는사람 · 보내는분전화번호 · 비고`

## 결정된 규칙 (중요)
1. **기록 전 사용자 확인 받기** — 정리한 표를 먼저 보여주고 "넣어" 하면 기록.
2. **검증은 전화번호 자릿수만** — 010은 반드시 11자리, `010-1234-5678`로 정규화. 주소·시도는 사람이 눈으로 확인. (시/도 화이트리스트 검사는 도 생략 주소를 헛걸러서 제거함)
3. **주소 juso API는 이 원격 세션에서 차단됨**(조직 egress 정책, `EGRESS_BLOCKED`/403). 로컬 PC나 허용 환경에서만 작동. 그래서 `add-checked`의 주소검사는 늘 SKIP.
4. **불확실·빈 칸은 노란음영** 으로 표시 — `peach.py highlight` 또는 직접 `batch_format`(`YELLOW` = {1.0, 0.95, 0.6}).
5. **가격 모델** — 박스당 40,000원 + 택배 5,000원(2박스까지 묶음). 예: 2박스=85,000, 1박스=45,000.
6. **붙여넣기 이미지/텍스트는 파일 경로가 없어** 판독팀 서브에이전트를 못 씀 → 오케스트레이터가 직접 판독. **손글씨 사진이 파일로 저장돼 올 때만** reader→checker→lead 체인 가동.
7. 자동 교정 금지 — 오타로 보여도 원문대로 넣고, 애매하면 확인 요청하거나 노란음영.

## 실행 메모
- 의존성: `pip install -r requirements.txt` (gspread, google-auth, python-dotenv, requests 등). 이 환경은 시스템 파이썬에 이미 설치돼 있어 `python3 peach.py ...` 로 실행.
- 기록: 주문을 JSON 배열로 만들어 `python3 peach.py add <파일.json>` (같은 날 이어 넣을 땐 `--no-separator`).

## 주문 화면 (구현 완료 — 자세한 건 `ui/README.md`)

`run_ui.bat` 더블클릭 → 브라우저. `--demo` 를 붙이면 자격증명 없이 화면만 본다.

**받기 / 검토 / 출고** 세 탭. 원래 계획은 "붙여넣기 → 미리보기 → 기록"이었지만,
그건 이미 대화로 잘 되는 부분이라 이득이 작았다. 실제로 손이 가던 3~4단계
(시트 재검토 · 택배사 엑셀 만들기)에 무게를 뒀다.

- **받기** — JSON/라벨/자유 형식을 줄마다 판단해 읽고, 기록 전 시트에서 중복을 찾아 보여준다.
  값은 교정하지 않는다. 자릿수 틀린 번호는 원문 그대로 넣고 빨갛게 표시.
- **검토** — 시트를 비추면서 빈칸(노랑)·전화오류(빨강)·중복묶음(파랑)을 얹는다. 칸을 눌러 바로 수정.
- **출고** — 날짜로 잘라 xlsx/csv. **빈칸이나 전화오류가 있으면 막는다**(확인하면 강행 가능).
  전화번호는 텍스트 서식으로 저장해 앞자리 0이 안 날아간다.

설계상 지킨 것:
- 업무 로직을 새로 만들지 않았다. 기록은 `peach.append_orders`, 검증은
  `validate.check_phone` — CLI 와 **같은 코드**를 지난다.
- `127.0.0.1` 전용. **삭제 기능은 화면에 없다**(CLI 로만).
- 새 의존성은 `openpyxl` 하나.

한계: **이미지는 화면에서 못 읽는다.** 판독은 계속 대화창에서 Claude 가 한다.
