# 아이 관리 웹앱 기획서

> 부부 둘이서 아이 하나(또는 여럿)의 월별 할 일·성장·생활을 한 곳에서 관리하는 모바일 웹앱.

---

## 1. 한 줄 정의

**"이번 달에 뭘 챙겨야 하는지"와 "잘 크고 있는지"를 부부가 같은 화면에서 보는 앱.**

기록 앱은 많지만 대부분 (1) 남편/아내 계정이 따로 놀거나 (2) 예방접종·영유아검진 같은
**기한이 있는 국가 일정**을 자동으로 안 챙겨준다. 이 앱의 핵심 차별점은 그 두 가지다.

## 2. 사용자 / 제약

| 항목 | 내용 |
|---|---|
| 사용자 | 아빠, 엄마 (2명). 조부모 열람은 v2 |
| 기기 | 거의 100% 휴대폰. 한 손 입력 |
| 입력 빈도 | 생활기록은 하루 several회, 성장기록은 주 1회, 일정 확인은 주 1회 |
| 운영 | 서버 비용 0원, 유지보수 최소 |
| 데이터 | 아이 건강정보 → 외부 서비스에 안 올림. 우리 구글 계정 안에만 |

## 3. 기술 스택 (결정)

**Google Apps Script Web App + Google Sheets (DB) + HTML Service (프론트)**

이미 `peach-bot/webform` 에서 쓰고 있는 것과 똑같은 구조라 배포·권한 흐름을 다시 배울 게 없다.

| | 왜 이걸로 |
|---|---|
| **Apps Script** | 서버·도메인·배포 파이프라인 전부 불필요. 구글 계정 로그인이 공짜로 따라옴 |
| **Sheets = DB** | 앱이 죽어도 데이터는 시트에 남는다. 손으로 고치고, 정렬하고, 내보낼 수 있음. 부부 데이터 규모(수년치 수천 행)면 성능 충분 |
| **트리거** | 매주 알림 메일, 구글 캘린더 동기화를 시간 기반 트리거로 공짜 처리 |
| **접근 제어** | 배포 시 "액세스 권한이 있는 사용자만" + 시트의 허용 이메일 화이트리스트 → 부부 2명만 |

**대안 검토 (안 가는 이유)**
- Next.js + Supabase/Vercel: 훨씬 좋은 UX를 만들 수 있지만 배포·인증·비용·유지보수가 붙는다. 나중에 옮길 수 있게 **모든 비즈니스 로직은 순수 함수로 분리**해 둔다.
- 노션/구글폼: 기한 자동 계산과 백분위 그래프가 안 된다.

**한계 (알고 시작)**
- Apps Script 웹앱은 첫 로딩이 1~3초로 느리다 → 초기 데이터를 한 번에 내려주고 화면 전환은 클라이언트에서 처리(SPA)
- `google.script.run` 은 동시 호출이 느림 → API를 하나로 묶은 `api(action, payload)` 단일 엔드포인트로 설계
- 파일(사진) 저장은 Drive 링크로만. 시트에 이미지 넣지 않는다

## 4. 기능 목록

### MVP (여기까지만 되면 이미 쓸만함)

#### A. 홈 — "이번 달 할 일"
- **지난 것(빨강) / 이번 주 / 이번 달 / 다가오는 것** 4단 구성
- 각 항목에 담당자(아빠/엄마) 지정 + 체크박스 한 번으로 완료
- 항목 출처 3가지:
  1. 자동 생성 — 예방접종, 영유아건강검진, 구강검진 (생년월일로 계산)
  2. 반복 — 매월 어린이집 원비, 분기별 보험 확인 등
  3. 수동 추가 — "이번 주 수족구 유행, 소아과 들르기"

#### B. 예방접종 자동 일정
- 생년월일 넣으면 **국가예방접종(NIP) 표준일정표 전체를 자동 생성**
- 백신별로 `권장 시작일 ~ 마감일` 구간을 날짜로 환산해 보여줌 → "지금이 창(window) 안인지" 한눈에
- 접종 완료 시 **접종일·기관** 기록 → 다음 차수 일정이 실제 접종일 기준으로 재계산
  (예: DTaP 2차는 1차 접종일 + 최소 4주 이후)
- 선택접종(로타, 수막구균 등) 토글 — 로타는 로타릭스(2회)/로타텍(3회) 선택에 따라 일정이 달라짐

#### C. 영유아 건강검진 / 구강검진
- 8차 건강검진 + 4회 구강검진의 **수검 가능 기간을 날짜로 환산**
- 기간이 지나면 무료 검진을 못 받으므로 **마감 3주 전 빨간 경고**

#### D. 성장 기록 + 백분위 트래킹 ⭐
- 입력: 측정일 / 키 / 몸무게 / 머리둘레(36개월 미만)
- 자동 계산: **BMI, z-score, 백분위** — 2017 소아청소년 성장도표(질병관리청) LMS 기준
- 그래프: 백분위 밴드(3·15·50·85·97) 위에 우리 아이 곡선을 겹쳐 표시
- **추세 해석**: "지난 3회 측정 동안 체중 백분위가 75 → 45로 떨어짐" 같은 변화 감지
  (곡선을 **가로지르며 떨어지는 것**이 절대 수치보다 중요한 신호)

### v1 (MVP 직후)

#### E. 생활기록 빠른 입력
한 화면에서 큰 버튼 탭 한 번으로 기록. 유형 하나의 테이블에 몰아넣어 유연하게.
- 수유/이유식 (모유·분유·이유식·밥, 양, 먹은 정도)
  - 처음 먹이는 재료는 체크해 두면 **3일간 관찰 목록**에 남는다. 나중에 뭐가 문제였는지
    역추적하려면 '언제 처음 먹였는지'가 남아 있어야 한다 — 구현 완료
- 수면 (시작/종료, 낮잠·밤잠)
- 배변 (횟수, 상태) — 돌 전엔 사실상 건강 지표
- 체온 (아플 때 시간대별로 찍히는 게 병원에서 제일 유용)
- 투약 (약 이름, 처방 용량, 복용 시각)
  - ⚠️ **용량 자동계산 기능은 넣지 않는다.** 처방받은 용량을 그대로 입력만.
    대신 "마지막 복용 3시간 전 / 다음 가능 시각" 타이머만 표시

#### F. 부부 인수인계
- 홈 상단에 **"오늘 요약"** — 마지막 수유/수면/배변/체온, 누가 기록했는지
- 한 줄 메모 ("오늘 낮잠 30분밖에 못 잠, 저녁에 보챌 수 있음")
- 밤 근무 교대하듯 서로 안 물어봐도 되게 하는 게 목적

#### G. 병원 이력
- 날짜 / 병원 / 증상 / 진단 / 처방약 / 비용 / 다음 예약
- 진료받을 때 "언제 뭐 때문에 왔었죠?"에 바로 답할 수 있음
- 처방약 이력이 쌓이면 항생제 반복 사용 패턴도 보인다

#### H. 알림
- 매주 월요일 아침 8시, **부부 둘 다에게 이번 주 할 일 메일**
- 마감 임박(D-7) 항목은 **구글 캘린더에 자동 이벤트 생성** → 휴대폰 기본 알림으로 뜸
- 카톡 알림은 비용/설정 부담 → 메일+캘린더로 충분

## 5. 데이터 모델 (구글시트 탭 = 테이블)

모든 테이블 1행은 헤더. `아이ID` 로 연결. 날짜는 전부 `yyyy-MM-dd` **문자열**
(시트 자동 날짜 변환으로 인한 타임존 사고를 막기 위해 해당 열은 서식 `@` 로 고정).

```
설정            키 | 값
                (허용이메일1, 허용이메일2, 타임존, 캘린더ID)

아이            아이ID | 이름 | 생년월일 | 성별 | 혈액형 | 알레르기 | 특이사항 | 활성

성장기록        기록ID | 아이ID | 측정일 | 키cm | 몸무게kg | 머리둘레cm | 측정장소 | 기록자 | 메모
                → 백분위는 저장하지 않고 조회 시 계산 (도표 갱신 시 전체 재계산 가능)

접종            접종ID | 아이ID | 백신코드 | 백신명 | 차수 | 창시작일 | 창마감일 |
                접종일 | 기관 | 상태(예정/완료/생략) | 메모

검진            검진ID | 아이ID | 구분(영유아/구강) | 차수 | 창시작일 | 창마감일 |
                수검일 | 기관 | 상태 | 결과메모

할일            할일ID | 아이ID | 제목 | 분류 | 기한 | 반복규칙 | 담당 |
                상태 | 완료일 | 출처(자동/수동) | 메모

생활기록        기록ID | 아이ID | 일시 | 유형(수유/식사/수면/배변/체온/투약/메모) |
                값1 | 값2 | 상세 | 기록자
                → 유형별로 값1/값2 의미가 다름 (수면: 시작/종료, 체온: ℃/부위, 수유: ml/종류)

병원            방문ID | 아이ID | 날짜 | 기관 | 증상 | 진단 | 처방 | 비용 | 다음예약 | 메모

일정완료        아이ID | 항목키 | 완료일 | 기관 | 기록자 | 메모
                → 접종·검진·행정을 한 테이블로. 항목키는 'DTaP#2', '영유아#4' 형태
```

마스터 데이터(표준접종일정·검진일정·LMS 표)는 시트가 아니라 **코드에 둔다**
(`src/data_schedule.gs`, `src/data_lms.gs`). 사람이 고칠 값이 아니고, 시트에서 읽으면
매 요청마다 왕복이 생기기 때문이다. 표가 개정되면 파일을 갱신하고 테스트를 다시 돌린다.

### 성장 백분위 계산

2017 소아청소년 성장도표(질병관리청·대한소아과학회)의 **LMS 파라미터**를 쓴다.
0~35개월은 WHO Growth Standards 기반, 3세 이상은 국내 측정치 기반.

```
L ≠ 0 :  z = ((X/M)^L − 1) / (L × S)
L = 0 :  z = ln(X/M) / S
백분위  =  Φ(z) × 100        (Φ = 표준정규 누적분포)
```

**구현 상태** — WHO Child Growth Standards 공식 LMS 표를 `src/data_lms.gs` 에 담았다 (35KB).
원본은 0~1856일의 일 단위 표라 그대로 넣기엔 커서, 오차를 재면서 격자를 줄였다:
0~31일은 매일, ~1년은 매주, 이후는 매월, 24개월(누운 키 → 선 키 전환)의 불연속 지점은
경계로 고정. 사이값은 L·M·S 선형보간. **원본 대비 최악 오차 0.008 z (백분위 0.04p)** 이며
`test/growth.reference.test.js` 가 전 구간에서 이를 검증한다.

남은 일: 한국 2017 성장도표는 0~35개월 구간에서 WHO 표준을 그대로 채택하므로 지금 값이
정확하지만, **만 3세 이상은 한국 고유 데이터(KDCA)** 라 현재 값은 근사치다.
아이가 세 돌을 넘기기 전에 KDCA LMS 표로 교체해야 한다.

## 6. 화면 구조

하단 탭 4개. 각 화면은 한 화면에 다 들어와야 하고, 스크롤은 목록에서만.

```
┌─────────────────────────┐
│  🏠 오늘   📈 성장   💉 일정   📝 기록  │
└─────────────────────────┘

🏠 오늘
  [아이 이름 · 생후 14개월 3일]
  ── 지난 것 (2)  ← 빨강
     · 일본뇌염 1차  (마감 D+5)      [아빠]
  ── 이번 주 (3)
     · 4차 영유아검진  (~11/30)       [엄마]  [완료]
  ── 오늘 요약
     마지막 수유 13:20 (아빠) · 낮잠 2h · 체온 36.8
     💬 "낮잠 짧았음. 저녁에 보챌 수도"

📈 성장
  [키 78.2cm  62p]  [몸무게 9.8kg  41p]  [머리둘레 46cm  55p]
  ── 그래프 (백분위 밴드 + 우리 아이 곡선)
  ── ⚠️ 체중 백분위 3회 연속 하락 (75 → 58 → 41)
  [+ 새 측정 입력]

💉 일정
  타임라인 — 완료(회색) / 지금 가능(초록) / 예정(흰색) / 지남(빨강)

📝 기록
  [🍼 수유] [😴 수면] [💩 배변] [🌡 체온] [💊 투약]   ← 큰 버튼, 탭 1회로 현재시각 기록
  ── 오늘 기록 목록 (탭해서 수정/삭제)
```

## 7. 리스크 / 주의사항

| 리스크 | 대응 |
|---|---|
| **의학 정보 오류** | 접종·검진 일정은 **참고용**임을 앱 하단에 항상 표기. 최종 확인은 소아과/예방접종도우미. 약 용량 자동계산은 구현하지 않음 |
| **LMS 표 오류** | 단위(cm/kg), 성별, 월령 오프셋이 틀리면 백분위가 통째로 틀림 → **알려진 검증값으로 단위테스트 필수** (예: WHO 남아 0개월 체중 중앙값 3.3kg → 50p) |
| **시트 날짜 타임존** | 모든 날짜는 문자열 `yyyy-MM-dd`, 시트 열 서식 `@` 고정, 스크립트 타임존 `Asia/Seoul` |
| **데이터 유실** | 주 1회 트리거로 스프레드시트 사본을 Drive 백업 폴더에 생성 (최근 8개 유지) |
| **개인정보** | 웹앱 배포는 "액세스 권한이 있는 사용자만". 추가로 `Session.getActiveUser().getEmail()` 을 허용 목록과 대조. URL 유출돼도 안 열림 |
| **동시 수정 충돌** | 부부가 동시에 기록할 수 있음 → 쓰기는 `LockService.getScriptLock()` 로 직렬화 |
| **기록 피로** | 생활기록은 "탭 1회로 현재시각 기록"이 기본. 상세 입력은 선택. 안 쓰게 되는 앱이 제일 나쁨 |

## 8. 만들지 않을 것 (스코프 방어)

- 다른 가족 초대, 권한 등급 시스템
- 푸시 알림 앱(네이티브), PWA 오프라인 동기화
- AI 상담/증상 진단
- 커뮤니티, 공유, 랭킹
- 약 용량 계산기

한 줄 요약: **부부 둘이 안 물어보고도 아는 상태**를 만드는 데 필요한 것만.
